Section 1 — Overview

The Lumina Digital Property Registry is a blockchain-based property registration and verification system deployed on the Ethereum Sepolia testnet. It enables a designated administrator to register property records on-chain, verify document integrity via SHA-256 hashing, moderate property status, and facilitate owner-authorized ownership transfers. Every property record is stored immutably on the Ethereum blockchain, ensuring transparency and tamper-proof verification.

The system replaces traditional centralized property registration with a decentralized, cryptographically verifiable registry where the smart contract is the single source of truth for property ownership, status, and document integrity.

1.1 Security and Integrity Layers

  1. Admin-Gated Registration — Only the designated contract administrator (0x127d6da08f6617A7fdB3EEf6b8Aaa7f172D51793) can register new properties. The onlyAdmin modifier enforces this on-chain.
  2. Owner-Authorized Transfers — Only the current on-chain owner can sign and execute a transferProperty() transaction. The admin can prepare a transfer request, but cannot execute it.
  3. SHA-256 Document Integrity — A supporting document is hashed client-side using the Web Crypto API. The resulting bytes32 hash is stored on-chain during registration and used for later verification.
  4. On-Chain Status Moderation — The admin can update a property's status to Registered (0), Disputed (1), or Suspended (2) via updatePropertyStatus(). Disputed or suspended properties cannot be transferred.
  5. Immutable Audit Trail — Every registration, status change, and ownership transfer emits a contract event (PropertyRegistered, PropertyStatusUpdated, PropertyTransferred) that is permanently recorded on the Ethereum blockchain.
  6. MetaMask Wallet Authentication — All write transactions require MetaMask signature confirmation. The connected wallet address is verified against the contract's admin address or the property's current owner address before any transaction.
  7. Dual-Layer Data Architecture — The smart contract stores core property data (owner, location reference, document hash, timestamp, status). Extended metadata (property name, description, images) is stored in browser localStorage and reconciled with on-chain data at runtime.

Section 6 — Demo Story (Implemented End-to-End)

  1. Connect MetaMask. Open the app at http://localhost:5173. Click "Connect Wallet" in the Registry System Banner. MetaMask prompts for account access. Ensure Sepolia network is selected.
  2. Register a property. Navigate to Register Property. Fill in: property title, location reference, property type, survey number, owner name, and owner wallet address. Upload a supporting document (PDF, image, etc.) — the SHA-256 hash is computed automatically. Click "Register on Blockchain". MetaMask prompts for transaction signing. After confirmation, a transaction receipt with Etherscan link is displayed.
  3. View the registered record. Navigate to Property Records. The newly registered property appears with its blockchain Property ID, status "Registered", and registration timestamp. Click "View" to see full details including on-chain owner address, registeredBy address, document hash, and ownership history.
  4. Verify document integrity. Navigate to Document Verification. Select the registered property by its blockchain ID. Upload the same document used during registration. The system computes the SHA-256 hash and compares it against the on-chain hash. A green "Hash Match Confirmed" indicates the document is identical to the registered version.
  5. Moderate property status. On the Property Records page or the property detail page, click "Change Status". Select "Disputed" or "Suspended", enter a reason, and confirm. MetaMask prompts for the updatePropertyStatus() transaction. The status badge updates after confirmation.
  6. Transfer ownership. Navigate to Ownership Transfers. Select a property (must have status "Registered"). The admin enters the proposed new owner's name and wallet address. The current on-chain owner must then connect their MetaMask wallet and sign the transferProperty() transaction. After confirmation, the ownership history updates and a new entry appears in the contract event log.
  7. Inspect analytics. Navigate to Registry Analytics. View on-chain metrics: total registered properties, status distribution, contract event history with transaction hashes and Etherscan links.

Section 8 — Smart Contract

One Solidity contract deployed on Ethereum Sepolia:

ContractPurposeKey Functions
PropertyRegistry Core property registration, ownership, status, and verification registerProperty(), getProperty(), verifyProperty(), updatePropertyStatus(), transferProperty(), getOwnershipHistory(), getPropertyCount()

8.1 PropertyRegistry

State Variables

  • admin (address) — immutable administrator, set in constructor
  • nextPropertyId (uint256) — auto-incrementing property counter
  • properties (mapping uint256 → Property) — core property storage
  • ownershipHistory (mapping uint256 → address[]) — ownership chain per property

PropertyStatus Enum

Registered (0), Disputed (1), Suspended (2)

Property Struct

propertyId, currentOwner, registeredBy, locationReference, documentHash (bytes32), registrationTimestamp, status (PropertyStatus)

Modifiers

  • onlyAdmin — restricts registerProperty() and updatePropertyStatus() to the admin address

Functions

  • registerProperty(initialOwner, locationReference, documentHash) → uint256 — Admin-only. Creates a new property record with auto-incremented ID. Records the initial owner, location, document hash, timestamp, and sets status to Registered. Emits PropertyRegistered.
  • getProperty(propertyId) → Property struct — Returns all fields for a given property ID.
  • getPropertyCount() → uint256 — Returns total number of registered properties.
  • verifyProperty(propertyId) → bool — Returns true if the property exists and has status Registered.
  • updatePropertyStatus(propertyId, newStatus, reason) — Admin-only. Changes property status. Emits PropertyStatusUpdated.
  • transferProperty(propertyId, newOwner) — Callable only by the current on-chain owner. Requires status = Registered. Updates currentOwner, appends to ownership history. Emits PropertyTransferred.
  • getOwnershipHistory(propertyId) → address[] — Returns the complete chain of previous owners.

Events

  • PropertyRegistered(propertyId, initialOwner, locationReference, documentHash)
  • PropertyStatusUpdated(propertyId, newStatus, reason)
  • PropertyTransferred(propertyId, newOwner)

Section 9 — Registry Data Service

The unified data layer is implemented in src/services/registryDataService.js. It reconciles on-chain smart contract data with browser localStorage metadata.

Key Functions

FunctionPurpose
getViableProvider() Returns a working Sepolia provider — MetaMask BrowserProvider if on Sepolia, else tries 4 public RPC endpoints with 2.5s timeout each
refreshRegistryData() Fetches admin address, property count, all on-chain properties (parallel), contract events (last 50,000 blocks), reconciles with localStorage. Publishes to all subscribed components.
useRegistryData() (React hook) Subscribes to the cached registry state. Returns records, metrics, events, loading/error state, and a refresh() function.
fetchSepoliaBalance(address) Returns the Sepolia ETH balance for any address
lookupOnChainProperty(propertyId) Direct on-chain property lookup by ID with ownership history
getCachedRegistryData() Returns the current cached state without triggering a refresh

Data Reconciliation Logic

  1. Fetch admin() and getPropertyCount() from the contract
  2. Fetch all properties in parallel using getProperty(1) through getProperty(n)
  3. Query PropertyRegistered, PropertyStatusUpdated, and PropertyTransferred events
  4. Match on-chain records to localStorage entries by blockchainPropertyId
  5. For on-chain records without local metadata, create synthetic records
  6. For local records without blockchain IDs, mark as "Registration Required"
  7. Compute consolidated metrics: registered, disputed, suspended, verified documents, transfers

Section 11 — Current Limitations

  • Single administrator: Only one admin address is hardcoded in the constructor; no admin rotation or multi-sig governance.
  • No backend persistence: Extended property metadata (name, description, images) is stored only in browser localStorage. Clearing browser data loses this metadata (on-chain data remains intact).
  • Public testnet: Deployed on Sepolia testnet; mainnet deployment would require gas cost considerations and security audit.
  • No IPFS/Arweave storage: Document files are not stored on decentralized storage; only the SHA-256 hash is recorded. The original document must be retained off-chain.
  • RPC dependency: The application depends on public Sepolia RPC endpoints. Rate limiting or downtime affects read operations. A fallback cascade of 4 RPC providers mitigates this.
  • No contract upgradeability: The smart contract is not upgradeable (no proxy pattern). Bug fixes or feature additions require redeploying a new contract.
  • Event query window: Contract events are queried for the last 50,000 blocks only. Older events may not appear in the frontend event feed.
  • Browser-only wallet: MetaMask (or compatible browser wallet) is required for all write transactions. Hardware wallet or mobile wallet support is not tested.
  • Transfer authorization gap: The admin-assisted transfer creates a local pending request, but the current owner must independently connect their wallet to sign. There is no notification system — the owner must be informed out-of-band.

12.2 Design Rationale

  • On-chain data is limited to what is legally and cryptographically essential: ownership, location reference, document hash, and status. This minimizes gas costs and keeps sensitive information off a public ledger.
  • Off-chain metadata enriches the user experience with property names, descriptions, and images without incurring blockchain storage costs. This data can be reconstructed or re-entered if lost.
  • Reconciliation happens at runtime in registryDataService.js, which merges localStorage entries with on-chain records using blockchainPropertyId as the join key.

Section 13 — Troubleshooting

Symptom / ErrorFix
"MetaMask is not installed" Install the MetaMask browser extension and refresh the page.
"Wrong network" / Chain ID mismatch Switch MetaMask to Sepolia Test Network (Chain ID 11155111). The app provides a "Switch Network" button.
"Only admin can perform this action" The connected MetaMask wallet is not the contract admin (0x127d...1793). Switch to the admin account.
"Transaction was rejected by the owner in MetaMask" The user clicked "Reject" in the MetaMask popup. Retry the action and click "Confirm".
"Cannot reach any Sepolia RPC endpoint" All 4 public RPC providers are unreachable. Check internet connection. The app falls back to cached localStorage data.
"Property not found on blockchain" The entered Property ID does not exist on-chain. Verify the ID using the property records page.
"Hash Mismatch Detected" The uploaded document differs from the one registered. Even a single byte change produces a different SHA-256 hash.
"Zero Hash / Document Not Registered" The property was registered without a document hash (0x000...000). Document verification is not available.
"Disputed or Suspended property cannot be transferred" The smart contract blocks transfers for non-Registered properties. Change the status back to Registered first.
"Only the current owner can transfer" The connected wallet does not match the property's on-chain currentOwner. The actual owner must connect their wallet.
Registration transaction fails with gas error The admin wallet may be out of Sepolia ETH. Use npm run sepolia:check-funding to check balance. Obtain more from a faucet.
MetaMask nonce error Reset the MetaMask account: Settings → Advanced → Clear Activity Tab Data.
Property appears locally but not on blockchain The property was saved to localStorage but the blockchain registration transaction was not completed. Re-register on the Register Property page.
